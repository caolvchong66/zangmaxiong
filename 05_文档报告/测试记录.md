## 2.1 采集几何与颜色（现场调试记录）

| 问题 | 现象 | 原因 | 处理 |
|---|---|---|---|
| 画面纵向拉伸 | 熊被拉长成 1:1.6 | OV5640 把 4:3 全幅压进 5:6 的 400×480 输出（驱动未设裁剪窗口） | 按输出宽高比写入 0x3800~0x3807 裁剪窗口（1620×1944 居中） |
| 检测框显示为蓝色 | 写入红色却显示蓝 | 面板/接口为 BGR 字节序 | 画框按 BGR 写字节；模型预处理同步做 R/B 交换 |
| 画面闪烁 | 检出时爆闪、平时也闪 | ①CPU 整帧拷贝刷屏抢带宽；②切换显示缓存重启动 VDMA | 显示直通不再拷贝；检测框改为 500 Hz 定时器直接叠加到实时帧，四角标记、小范围 cache 刷写 |
| 检测框被“吃掉” | 框时有时无 | 摄像头 VDMA 每帧覆盖整个帧缓存，CPU 叠加的框会被覆盖 | 提高重绘频率到 500 Hz、只画四角短线段并只刷对应小区域，实测可稳定显示（边缘偶有断线） |
| 横躺的熊检不出 | max 仅 0.05 | 训练集均为正立目标，对 90° 旋转不鲁棒 | 现场取景要求目标正立 |

几何修正前后同一帧离线推理对比：0.078（拉伸）→ 0.838（校正后）。

## 2.2 识别精度与速度优化

| 优化项 | 做法 | 效果 |
|---|---|---|
| 输入分辨率 | 320 → 256 定稿（网络全卷积，锚点/解码按特征图尺寸重算；192 亦试过） | 单帧 4.0 s → 3.0 s（192 时 2.1 s） |
| 精度保持 | 同一张验证图离线对比 | 0.896（320）/ 0.892（256）/ 0.890（192），基本无损 |
| 误检抑制 | 置信度阈值 0.28；最小框 20 px；长宽比限制 ≤2.8 | 衣服、桌面等弱响应被过滤 |
| 检测框叠加 | 500 Hz 定时器只画四角短线并小范围刷 cache | 叠加不抢带宽、不引起闪烁 |
| 屏幕摩尔纹 | 手机屏幕被拍摄时产生横向条纹，同一画面置信度在 0.25~0.67 间跳动 | 预处理改为**连续 3 帧平均**，置信度稳定在 0.5~0.92 |
| 画面旋转 | 熊横躺 90° 时置信度仅 0.10~0.37 | 取景要求目标正立（90° 旋转重试为后续可选功能） |
板上实测：置信度 0.31~0.61；改用连续 3 帧平均后稳定在 0.5~0.92，连续 3 帧触发 ALARM。

## 6. 已知问题与改进方向

1. LCD 的 ID 在**上电/复位时读取一次**，热插拔屏幕后必须复位才会切换分辨率；
2. 推理以单核标量调度为主，A9 上 256×256 INT8 约 3 s/帧（320×320 时约 4 s），后续可将卷积卸载到 PL（HLS 卷积 IP 已在工程中预留）；
3. 当前 0.33 fps 满足"静态/缓行目标"预警；预览为直通实时显示，检测到目标时定格画框；若需更高刷新率，可降到 192×192 输入或把卷积卸载到 PL；
4. 曾尝试用 CPU 每 12 Hz 整帧拷贝刷屏，因与显示 VDMA 抢 AXI/DDR 带宽导致闪烁与撕裂，已改为直通方案；
4. 当前只用左目，不再涉及双摄同步。
