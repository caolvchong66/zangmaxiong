# 藏马熊识别与预警装置 —— 系统使用说明

适用平台：正点原子 ATK-DF7020-484（ZYNQ-7000 XC7Z020CLG484-1）
工具链：Vivado 2020.2 / Vitis 2020.2
摄像头：OV5640 ×2（DVP 接口）    显示：RGB LCD（4.3/7/10.1 寸，自动识别）

---

## 1. 系统能做什么

1. 单路 OV5640（左目）实时采集，PL 内完成 DVP 时序解析、RGB565→RGB888 转换，经 AXI VDMA 写入 DDR；
2. 显示通道 VDMA 直接扫描同一块帧缓存送到 RGB LCD，**零拷贝**预览；
3. PS（Cortex-A9）对摄像头画面做 letterbox 预处理后，用自研 **INT8 推理引擎**运行 YOLOv8n 藏马熊模型（256×256）；
4. 后处理做置信度过滤 + NMS，把检测框反变换回摄像头坐标，**直接画在 LCD 帧缓存上**（红框）；
5. 连续若干帧检出即判定"预警"，输出报警日志，并把标注帧写到固定 DDR 地址供上位机读取；
6. 预览零拷贝：显示 VDMA 直接扫描摄像头帧缓存（整屏显示左目摄像头画面（800×480 整幅采集））；每约 3 秒推理一次，**检出目标时画面定格并叠加红框**，无目标时回到实时画面；
7. 全程无需操作系统（裸机 standalone），上电即运行。

## 3. 快速运行（比赛现场）

### 3.1 用 SD 卡启动（推荐）
1. 把 `01_程序烧录/BOOT.bin` 拷贝到 SD 卡根目录（FAT32，卡 ≤32GB）；
2. SD 卡插入开发板，启动模式拨码设为 SD 启动；
3. 上电，约 3~5 秒后 LCD 出现摄像头画面，检测框随之刷新。

### 3.2 用 JTAG 调试运行
在 Vitis 中打开 `02_工程源码` 的工程，或直接用 xsdb：

```tcl
connect
targets -set -filter {name =~ "APU*"}
rst -system
fpga -file bear.bit
targets -set -nocase -filter {name =~ "ARM*#0"}
source ps7_init.tcl
ps7_init
ps7_post_config
dow bear_app.elf
con
```

### 3.3 没有 LCD 时怎么看结果
运行 `04_上位机工具/bear_monitor.py`（需要 hw_server 已启动、JTAG 已连接），
它会通过 JTAG 读取板卡 DDR 中的标注帧并弹窗显示，同时打印检测日志。

### 3.4 蜂鸣器报警（本次新增）
蜂鸣器模块接在 J21 的 **PL_TX** 孔上，对应 FPGA 的 **E18** 引脚：

| 蜂鸣器模块 | 接到 |
|---|---|
| VCC | 3.3V |
| GND | GND |
| BP(BEEP) | J21 的 PL_TX 孔（E18） |

- 上电/复位后先响 **120 ms 自检音**（2 kHz）；
- 一旦检出藏马熊**立即开始持续报警**；熊离开画面约 6 s 后自动停止（不再等 3 帧确认）；
- 无源蜂鸣器，用 2 kHz 方波驱动，直流电平即静音，不需要区分高低电平有效；
- 详细改动与排错见 `05_文档报告/蜂鸣器接入说明.md`。

## 4. 关键设计

### 4.1 硬件数据通路
```
OV5640 #0 ─┐
           ├─ DVP → ov5640_capture_data(IP) → AXI4-Stream → VDMA(S2MM) → DDR 帧缓存 0x01100000
OV5640 #1 ─┘                                                    │
                                                                ├→ VDMA(MM2S) → v_axi4s_vid_out → rgb2lcd → LCD
                                                                └→ PS 预处理 → INT8 推理 → NMS → 画框（写回同一帧缓存）
```
- SCCB 由 PS 通过 EMIO 软件模拟（SCL0/SDA0 = EMIO54/55，SCL1/SDA1 = EMIO56/57）；
- 像素时钟由 clk_wiz 按 LCD 分辨率动态配置；
- LCD ID 由 AXI GPIO 读取，支持 480×272 / 800×480 / 1024×600 / 1280×800。

### 4.2 模型
- 训练：Ultralytics YOLOv8n，单类 `zangmaxiong`，imgsz=640，50 epoch；
- 导出：ONNX（固定输入 1×3×320×320，输出 1×5×2100）→ NCNN INT8（`bear-int8.param/bin`）；
- 本装置实际部署：由 ONNX 权重做**逐输出通道对称 INT8 量化**，生成 `weights.bin`，
  由自研引擎在 A9 上解释执行（不依赖 ncnn 运行时、不需要操作系统）；
  网络全卷积，**板端实际按 256×256 推理**（1344 anchors），320×320 是 ONNX 的导出/对照尺寸。

### 4.3 推理引擎
- 算子：Conv(3×3/1×1, stride 1/2, pad 1)、SiLU、C2f、SPPF(MaxPool 5×5)、nearest Upsample、
  Concat、DFL(softmax 加权和)、dist2bbox、Sigmoid、NMS；
- 量化：权重 INT8 + 每通道 scale；激活值**逐张量动态对称量化**（运行时统计 amax），
  int8×int8→int32 累加，ARM NEON `vmlal_s16` 一次 16 个 MAC；
- 精度：与 ONNX Runtime 逐层比对，中间张量相关系数 > 0.99，最终输出相关系数 0.999，
  最大类别概率误差 < 0.02。

### 4.4 预警逻辑
- 置信度阈值 0.28（可调），IoU 0.45 贪心 NMS；
- 连续 3 帧检出 → 置预警标志，日志输出 `ALARM`，LCD 红框加粗；
- 预留 GPIO 报警输出（LED/蜂鸣器），需在 PL 增加 AXI GPIO 后启用。

## 6. 常见问题

| 现象 | 排查 |
|---|---|
| LCD 画面半花/半黑 | 屏幕必须在上电前接好：LCD ID 只在启动时读一次，热插拔后需复位；日志 `video mode` 应等于面板分辨率 |
| LCD 无显示 | 读日志 `LCD ID`，为 0 表示未接屏或 ID 脚未连通；确认 FPC 排线 |
| 画面全黑 | 摄像头未初始化成功，看日志 `cam0/cam1` 是否为 0 |
| 画面撕裂/闪烁 | 不要用 CPU 周期性整帧拷贝刷屏（会与显示 VDMA 抢带宽）；本项目已改为直通显示 |
| 检测不到 | 目标过小/过暗；降低阈值；确认模型为单类藏马熊 |
| JTAG 连不上 | 先启动 hw_server，确认 JTAG-HS1 驱动与排线 |

## 7. 已验证的结果

- 双路 OV5640 初始化成功（SCCB 读到 0x5640）；
- 摄像头帧缓存持续刷新（CRC 逐秒变化）；
- 静态图测试：置信度 0.889，框位与 PC 端 ONNX Runtime 一致；
- 板上推理耗时：见 `05_文档报告/测试记录.md`。
