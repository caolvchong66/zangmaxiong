# 答辩速查卡（一页纸）

## 一句话介绍
基于 ZYNQ-7000（XC7Z020）的藏马熊识别与预警装置：单路 OV5640（左目）采集 → PL 采集 IP + VDMA → DDR 帧缓存 → 800×480 LCD 实时直通显示；PS 端自研 INT8 推理引擎运行 YOLOv8n 单类模型，检出藏马熊即画框并触发预警，整机裸机运行、上电即工作。

## 关键数字（背下来）
| 项目 | 数值 |
|---|---|
| 主芯片 | XC7Z020CLG484-1（A9 双核 667MHz + PL） |
| 摄像头 | OV5640 ×2，各输出 400×480（DVP，RGB565→RGB888） |
| 显示屏 | 7 寸 RGB LCD 800×480（LCD ID 0x7084，自动识别） |
| 模型 | YOLOv8n，单类"藏马熊"，3.02 M 参数，INT8 权重 3.04 MB |
| 训练精度 | mAP@0.5 = 0.68，mAP@0.5:0.95 = 0.397，P 0.758 / R 0.652 |
| 部署输入 | 256×256，1344 anchors（stride 8/16/32），输出 5×1344 |
| 推理速度 | 单帧约 3.0 s（纯推理约 2 s），0.33 fps；跟踪 30 fps |
| 精度一致性 | 与 ONNX Runtime 相关系数 0.9994；同图 0.892 vs 0.896 |
| 整机功耗 | 约 3.5 W（估算） |

## 三个技术亮点（评委常问"难点在哪"）
1. **几何畸变定位**：OV5640 把 4:3 全阵列塞进 5:6 的 400×480，画面纵向拉伸 1.6 倍；驱动未设 ISP 裁剪窗口。按输出宽高比写 0x3800~0x3807（1620×1944 居中）后，同一帧置信度 0.078 → 0.838。
2. **无框架 INT8 推理引擎**：不依赖 ncnn/OS，纯 C + NEON；逐通道对称 int8 权重、逐张量动态激活量化，int8×int8→int32 累加，8 通道分块 GEMM + im2col。
3. **预览与检测解耦**：显示 VDMA 零拷贝直通（不闪），检测框由 500 Hz 定时器只画四角短线并小范围刷 cache；检测每 3 s 一次，中间用 30 fps 去均值 SAD 跟踪器保持跟随。

## 常见追问
- **为什么不用 ncnn？** 裸机没有文件系统/线程/算子库，ncnn 依赖 C++ 标准库与多线程；自研引擎只保留本网络需要的算子，代码 16 KB、启动即用。
- **为什么 3 秒才一帧？** 纯 PS 端 1.09 GMAC（320）/0.44 GMAC（256）在 667MHz A9 上受 DDR 带宽限制；后续把卷积卸到 PL（工程里已有 HLS conv2d_stream IP）可到 10 fps 量级。
- **误检怎么压？** 阈值 0.28 + 最小框 20 px + 长宽比 ≤2.8 + 时序一致性（弱检需相邻两帧位置吻合）。
- **为什么识别率不稳？** 拍手机屏幕会有摩尔纹，同一画面置信度在 0.25~0.67 跳动；已用连续 3 帧平均抑制，稳定到 0.5~0.92。现场建议用打印照片。
- **横着的熊为什么检不出？** 训练集全为正立目标，实测旋转 90° 置信度只剩 0.10~0.37；现场要求目标正立。

## 现场演示流程（30 秒版）
1. 上电 → 屏幕出现左目摄像头实时画面（左=摄像头0，右=摄像头1）；
2. 把熊照片（正立、占画面 40% 以上、尽量用打印件）对准左摄像头；
3. 约 3 秒后出现红色四角框，框随目标移动（30fps 跟踪）；
4. 连续 3 帧确认后日志输出 ALARM，即预警触发。
